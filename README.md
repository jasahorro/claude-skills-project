# Claude Code Skills

A [NextWork](https://nextwork.ai/projects/5bae2568-dd25-5e78-80f4-66a02afac9ca?track=high) project: **Claude Code Skills Basics**.

I built three custom [Claude Code](https://claude.com/claude-code) skills that automate a small git workflow. Two skills each do one job, and a third chains them into a pipeline.

## The skills

| Skill | What it does |
|---|---|
| [`/smart-commit`](.claude/skills/smart-commit/SKILL.md) | Reviews `git status` and `git diff`, stages everything, and commits with a conventional commit message such as `feat(app): add multiply function`. |
| [`/changelog`](.claude/skills/changelog/SKILL.md) | Reads the git history and regenerates `CHANGELOG.md` with the commit history, working tree status, and a description of each tracked file. |
| [`/dev-pipeline`](.claude/skills/dev-pipeline/SKILL.md) | Runs `/smart-commit`, then `/changelog`, then prints a summary. |

### How the pipeline coordinates them

`/dev-pipeline` doesn't do the work itself. It calls the other two skills in order:

1. **`/smart-commit`** commits the current changes.
2. **`/changelog`** then reads `git log`, so the commit from step 1 is included.

The order matters. If the changelog ran first, it would miss the newest commit. Because each skill has one job, they can also be used on their own.

## Try it

```bash
git clone https://github.com/jasahorro/claude-skills-project.git
cd claude-skills-project
claude
```

Claude Code picks up the skills in `.claude/skills/` automatically. Make a change, for example to `app.py`, then type:

```
/dev-pipeline
```

## Project files

- `app.py`: a small Python script with `greet`, `add` and `multiply` functions, used as sample code for the pipeline to commit.
- `CHANGELOG.md`: generated by the `/changelog` skill.
- `.claude/skills/`: the three skills.

## What I learned

At first none of the skills triggered on their own, and they showed up in Claude Code with the description `\---`. The `SKILL.md` files started with `\---` instead of `---`. The backslash had been added when the text was copied in, and it broke the YAML frontmatter, so Claude Code couldn't read each skill's `name` or `description`. Without a description, Claude has nothing to match a request against, so the skill is never picked automatically.

After I removed the escaping backslashes, all three skills loaded with their real descriptions and `/dev-pipeline` ran from start to finish.

**Takeaway:** a skill's frontmatter is how Claude decides when to use it. If a skill isn't triggering, check the header first.
